# Лабораторная работа №1: Источники задач и контракты

## Цель работы

Освоить duck typing и контрактное программирование на примере источников задач.

## Описание

Данный проект реализует простую подсистему приема задач. Задачи могут поступать из разных источников (файлы, API-заглушки, генераторы). Ключевая особенность состоит в том, что все источники должны соответствовать единому контракту, определенному с помощью `typing.Protocol`, без использования общего базового класса или наследования. Система также включает runtime-проверку соблюдения этого контракта.

## Структура проекта

*   `lab1.py`: Основной код, реализующий источники задач, протокол и систему обработки.
*   `test_lab1.py`: Набор юнит-тестов для проверки корректности работы компонентов.
*   `requirements.txt`: Список зависимостей проекта (для данной работы он пустой).

## Запуск

Для запуска и тестирования проекта выполните следующие шаги:

1.  **Убедитесь, что установлен Python 3.x.**

2.  **Поместите все файлы (`lab1.py`, `test_lab1.py`, `requirements.txt`) в одну папку.**

3.  **Создайте и активируйте виртуальное окружение** (рекомендуется):

    ```bash
    python -m venv venv
    # Активация для Linux/macOS:
    source venv/bin/activate
    # Активация для Windows (PowerShell):
    .\venv\Scripts\Activate.ps1
    # Активация для Windows (cmd.exe):
    venv\Scripts\activate.bat
    ```

4.  **Установите зависимости:**
    ```bash
    pip install -r requirements.txt
    ```
    (Для данного проекта `requirements.txt` пуст, так как используются только стандартные библиотеки Python.)

5.  **Запустите основной модуль:**
    ```bash
    python lab1.py
    ```
    Вы увидите вывод обработки задач из различных источников.

6.  **Запустите тесты:**
    ```bash
    python -m unittest test_lab1.py
    ```
    Убедитесь, что все тесты успешно пройдены.

## Основные использованные концепции

*   **Duck Typing:** Объекты определяются по их поведению (наличию определенных методов), а не по типу или иерархии наследования.
*   **`typing.Protocol`:** Формальное описание контракта (интерфейса) для использования с Duck Typing.
*   **`@runtime_checkable`:** Декоратор, позволяющий проверять соответствие протоколу во время выполнения программы с помощью `isinstance()`.
*   **`dataclasses`:** Удобный способ создания классов-контейнеров для структурированных данных.
