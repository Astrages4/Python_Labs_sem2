## Лабораторная работа №2: Модель задачи: дескрипторы и @property

### Цель работы

Освоить управление доступом к атрибутам и защиту инвариантов доменной модели с помощью дескрипторов и свойств.

### Описание

Модель задачи `Task` была переработана. Вместо простого `dataclass` теперь используется полноценный класс с внутренней логикой валидации и инкапсуляции.

*   **Дескрипторы** используются для валидации полей `description`, `priority` и `status` при их создании или изменении.
*   **Свойства (`@property`)** используются для создания вычисляемого поля `is_ready_to_start` и для защиты поля `id` от изменений.
*   **Пользовательские исключения** (`InvalidPriorityError`, `InvalidStatusError`) генерируются при нарушении правил (инвариантов).
*   Продемонстрировано различие между **data-дескрипторами** (например, `ValidatedPriority`) и **non-data дескрипторами** (`CreationTime`).

### Запуск

1.  **Запустите основной модуль для демонстрации:**
    ```bash
    python lab2.py
    ```
    В выводе будут показаны примеры успешного создания задачи, а также перехват ожидаемых ошибок при попытке установить некорректные данные.

2.  **Запустите тесты:**
    ```bash
    python -m unittest test_lab2.py
    ```
